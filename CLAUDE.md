# Расписание ГУУ — Telegram Mini App + бот

Расписание всего ГУУ (бакалавриат ОФО/ОЗФО, магистратура, аспирантура; началось с **МБ(МП) 1-1/1-2**).
План новой версии и ход работ — `docs/roadmap.md`.
Мини-приложение в Telegram (@GUU_Scheduule_bot, кнопка меню и `/start`) + бот: команды, inline,
автосообщения в беседы групп, живой календарь, рейтинг преподавателей, админ-панель владельца.
Всё бесплатно: GitHub Pages + бесплатный тариф Cloudflare Workers / D1 / KV.

## Архитектура

| Часть | Где | Что |
|---|---|---|
| Фронт | `src/` (React 19, Vite 8, TypeScript) | мини-приложение, хостинг — GitHub Pages `https://kkreal75-droid.github.io/guu-schedule/` |
| Общая логика | `shared/` | `schedule-core.ts` (формат, правки, недели, пары на день), `groups.ts` (id групп, МБ), `format-core.ts` — одна для фронта и бота |
| Бот | `bot/` (Cloudflare Worker `guu-schedule-bot`) | `https://guu-schedule-bot.guu-schedule-bot.workers.dev`, вебхук Telegram |
| Данные расписания | `public/data/` | вывод `update.py` + `guu_parser.py` из всех файлов guu.ru (см. ниже) |
| Старый формат | `schedule.json` (корень) | только МБ(МП) 1-1/1-2 — для версий приложения, закэшированных в Telegram |
| Ручные правки | `overrides.json`, `overrides/thursday.json`, `overrides/thursday-1-2.json` | накладываются поверх файлов групп (см. ниже) |
| Автообновление | `update.py` + `.github/workflows/deploy.yml` | раз в час проверяет guu.ru |
| Служебное | `data/state.json`, `data/group_ids.json`, `data/teacher_history.json`, `data/doc-cache/`, `data/i18n/` | SHA файлов ГУУ, реестр id групп, у каких групп вёл преподаватель (текущий и прошлый семестр), .doc → .docx |

**Данные (`public/data/`, Vite кладёт на сайт как есть).** `groups.json` — все группы (id, имя, уровень,
форма, курс, институт, программа); `schedule/<id>.json` — пары группы + сетка времени по дням (номер
пары — по ней: у вечерних 18:50 — 1-я); у пары `stream: true` — языковой блок потока («Иностранный язык…» без
преподавателя или «на этаже» стоит одинаково у ≥ 2 групп в нескольких окнах, студент ходит в одно; update.py);
место «ЛК-6 этаж» / «У 6 этаж» → «ЛК, 6 этаж» (только если в ячейке нет настоящей аудитории; в `rooms.json` не идёт); `teachers.json` + `teachers/<id>.json`; `rooms.json` (аудитория →
занятость, недели битовой маской); `session/<id>.json` — сессия только текущего учебного года (все даты не
раньше начала семестра; прошлогодние файлы guu.ru — архив, по совпадению имени их группам НЕ показывать);
`session_status.json` — что на странице сессии guu.ru («весенняя сессия прошлого года»), у каких групп сессия;
`calendar.json` — первая и последняя пара каждого курса (учебный график, см. ниже);
`subjects.json` — все предметы и какие без английского перевода (этап 11);
`parse_report.json` — что разобрано по файлам/листам и где парсер не уверен (и «Другое → Документы»);
`kug.json` — календарные учебные графики программ (PDF с guu.ru/sveden/education/, раз в сутки); `places.json` —
места кампуса для «Корпусов ГУУ» (ведётся руками, update.py не трогает; `todo` — что не проверено) и `campus.json` —
схема кампуса из OpenStreetMap (`scripts/campus_map.py`, запускать вручную); `alerts.json` — тревоги,
бот присылает их владельцу (cron раз в 10 мин, отправленные — KV `alerts-sent`).

**Группы.** id стабильный (`b1-mb-mp-1`: b — бакалавриат ОФО, z — ОЗФО, m — магистратура, a — аспирантура;
курс; аббревиатура программы; номер), выдаётся один раз — реестр `data/group_ids.json`. Имя — «МБ(МП) 1-1»,
«ГМУ 2-3», «… ОЗФО», «… маг.». МБ(МП) 1-1/1-2 раньше хранились по имени: `shared/groups.ts`
(`normalizeGroup`) понимает старые имена везде (D1, KV, старые версии приложения), миграция 0005 перевела D1.
Ключи заметок и UID календаря у МБ считаются, как раньше (от «МБ(МП) 1-1» / «1-1»).

**Онбординг** (`src/onboarding/`, решение — `src/main.tsx`): настройки на устройстве/в облаке Telegram (новее
— по `at`) → выбор, который помнит бот (`me`) → регистрация, если бот говорит `onboarding` (новый: не `legacy`,
ни группы, ни роли) или бот недоступен и на устройстве нет следов старой версии → иначе МБ 1-1, как раньше.
**Знакомство** (этап 7.1, `Intro.tsx`): всем один раз — 4 истории автора → новым регистрация, остальным «Это
твоя группа?» (Да / Сменить) → тур из 3 экранов → расписание. Видел ли — max(localStorage `intro`, CloudStorage
`intro`, D1 `users.intro_version`) ≥ `INTRO_VERSION` (`src/intro.ts`, сейчас 2); `POST /intro` — только вверх.
Админка → «Сбросить мой онбординг»; «Профиль → Показать знакомство ещё раз».
Регистрация: «Кто ты?» → студент: 7 шагов форма → уровень → курс → институт → направление → программа → группа
(«Шаг N из 7», хлебные крошки, шаг с одним вариантом выбирается сам; «Знаю свою группу» — поиск) → карточка
«Это твоя группа…» → «Сохранить». Преподаватель — поиск по
фамилии, главный экран — его пары (`t-<id>`, у пары вместо преподавателя — группы). Профиль → «Параметры
аккаунта» (`src/onboarding/AccountForm.tsx`): «Я студент / Я преподаватель», выпадающие списки по тем же шагам
(`STEPS` из Onboarding.tsx) или ФИО с поиском → «Сохранить»; «Знаю свою группу» — онбординг сразу с поиска.
Версия в профиле — `__BUILD__` (vite.config.ts: package.json + дата + коммит). Над расписанием: у МБ — «1-1 / 1-2», у остальных — своя группа + избранные (до 5). `access`
(free_forever — МБ и все, кто был до онбординга; standard — остальные) и `PAYWALL_ENABLED=false` — только
структура, ни на что не влияют; владелец меняет access в карточке пользователя. Рассылка — всем / 1-1 / 1-2 /
фильтр (уровень, форма, курс, институт или группа). «Ещё → Сессия» — `data/session/<id>.json` или заглушка.
«Ещё»: Расписание группы (поиск + «☆ В избранное»), Расписание преподавателя, Свободные аудитории (`rooms.json`) —
чужое расписание показывает тот же `ScheduleScreen` с отдельным `Timetable` (`readOnly`, без заметок).

**Сайт.** Приложение качает `data/schedule/<id>.json` своих групп при каждом запуске (`?v=<время>`,
`no-store`, копия в localStorage на случай без сети) и шлёт в `/seen` `v: 2` (правки — по id); правки
встроены в бандл. Бот берёт файлы групп по требованию и правки с сайта (кэш CDN 120 с + 60 с в памяти).

**GitHub Actions (`deploy.yml`).** push в main → сборка и деплой Pages; cron `17 * * * *` →
`update.py` → коммит `public/data`, `schedule.json`, `data/`, только если что-то изменилось → деплой;
LibreOffice ставится, только если изменился .doc (нет в `data/doc-cache/`); `workflow_dispatch`
(вход `force`) — то же вручную (кнопка «Обновить сейчас» в админке).

**update.py.** Берёт все .xlsx/.doc/.docx со страниц `/student/schedule/` и `/student/session/` (раздел —
по заголовкам «Бакалавриат / Магистратура / Аспирантура»), сравнивает SHA-256 с `data/state.json`; если
что-то поменялось — разбирает всё (`guu_parser.py`, ~3 с). Файл не публикуется (остаются прошлые группы
этого файла, владельцу тревога), если групп стало на >10% меньше или у МБ(МП) 1-1/1-2 < 30 пар.
Дубли групп из двух файлов — берётся более свежий. `--local DIR` — файлы из папки. User-Agent без слова
«bot» (иначе guu.ru даёт 403), SSL через certifi. Локально .doc: `SOFFICE=…/soffice`.
**`parser.py` не менять — логика проверена**; `guu_parser.py` импортирует из него разбор недель и даёт
для МБ(МП) 1-1/1-2 ровно тот же результат (95 пар; проверка — сравнение с `parser.parse_workbook`).

**Воркер — эндпоинты** (`bot/src/index.ts`):
- `POST /webhook` — обновления Telegram (секрет в заголовке = SHA-256 от `webhook:`+токен);
- `POST /seen` — открытие приложения: initData → визит; ответ `{banned, admin, me, edits, subgroups, tags, hidden,
  my_hidden, notice, maintenance}` (`me` — роль, группа, преподаватель, access, нужен ли онбординг; `hidden` — скрытое
  владельцем для всей группы, `my_hidden` — свои скрытые пары);
- `POST /hidden/add {group, date, start, subject, kind, scope}` | `/hidden/delete {id}` — «Это не моя пара» (`hidden.ts`);
- `POST /profile` — выбор из онбординга `{role, group | teacher}` (группа/преподаватель должны быть на сайте);
  `POST /intro {version}` — знакомство просмотрено; `POST /lang {lang}` — язык интерфейса (ru / en, этап 11);
- `POST /starosta/<info|edit-add|edit-delete|subgroup-add|subgroup-delete|tag-add|tag-delete>` — староста своей группы;
  `POST /my-subgroups` — свои подгруппы; `POST /extras {groups}` — правки и подгруппы групп (просмотр чужой);
- `POST /cal/status|connect|disconnect`, `GET /cal/<токен>.ics`, `GET /cal/<токен>/apple` (страница webcal для iPhone);
- `POST /reviews/<top|teacher|save|delete|report|vote>` — рейтинг преподавателей (`reviews.ts`);
- `GET /places` — правки мест «Корпусов ГУУ» поверх `data/places.json` (`places.ts`, D1 `place_edits`), кэш 60 с;
- `GET /academic` — правки учебного графика (`academic.ts`, D1 `calendar_edits`), кэш 60 с;
- `GET /translations` — правки английских названий ГУУ (`translations.ts`, D1 `translations`), кэш 60 с;
- `GET /health` — жив ли воркер и D1 (для мониторинга);
- вход защищает `guard.ts`: лимит тела (64 КБ, вебхук 1 МБ, админка 12 МБ), CORS только для origin `WEBAPP_URL`,
  лимиты Workers Rate Limiting (`RL_*` в wrangler.jsonc: по IP щедро, по пользователю, строже на запись) — 429 до D1;
  публичное (`/places`, `/academic`, `.ics`) — из памяти изолята с ETag;
- `POST /support {text}` — «Написать в поддержку»: владельцу в бот с кнопкой «Ответить» (`sp:reply:N`), ответ
  владельца (reply на «✍️ Ответ на обращение №N») бот пересылает автору (`support.ts`, ≤5 в сутки); ответ можно поставить в очередь — `UPDATE support_messages SET reply_text = '…' WHERE id = N`,
  cron отправит его автору тем же сообщением «💬 Ответ на твоё обращение» и отметит владельцу;
- `POST /admin/<…>` — админ-панель (`admin-api.ts`), только OWNER_ID, остальным 403 на любой адрес;
- `GET /` — setWebhook + меню команд (`?force` — заново) + строка о данных в описании бота;
- cron `* * * * *`: сводки в беседы, раз в 10 мин (минута %10 = 5) сверка изменений на 7 дней
  (снимки — D1 `group_snapshots`, только группы с беседами, по 15 за запуск) и тревоги автообновления,
  в :x3 — сверка расхода лимитов (`usage.ts`: на 80% — тревога владельцу и режим экономии: визиты не пишутся,
  .ics из кэша), в 00:20 UTC — бэкап D1 владельцу в личку (`backup.ts`, `docs/backup.md`),
  в :x7 — рассылка «📚 Опубликовано расписание сессии» группам, у которых она появилась (`session.ts`, KV
  `session-notified`, кнопка мини-приложения `?open=session`), в :35 — чистка журнала (`journal.ts`: повторы обновлений, журнал старше года, сообщения бывшего чата старше 30 дней), плюс скрытые «только в этот день» старше
  30 дней, каждую минуту — ответы поддержки из очереди, остаток лимита — досылка рассылок (≤30 сообщений за запуск,
  пауза 50 мс).

**D1 `guu-bot`** (миграции `bot/migrations/0001…0024`; 0006 — `users.role/teacher_id/access/legacy/onboarded_at`, 0007 — старосты, подгруппы, 0008/0009 — чат вместо досок (чат удалён в этапе 9, таблицы `board_*` остались), 0010 — отзывы, 0011 — `users.intro_version`, 0012 — `sport_sections`, `sport_sessions` (с 8.1 не используются), 0013 — `support_messages`, 0014 — критерии отзывов и `review_votes`, 0015 — `place_edits`, 0016 — `broadcasts.button`, 0017 — `calendar_edits`, 0018 — `tg_updates`, `admin_log`, `usage_daily`, 0019 — индекс псевдонимов чата, 0020 — `hidden_lessons`, 0021 — `support_messages.reply_text`, 0022 — `users.lang` (выбранный язык), `users.lang_code` (язык Telegram), 0023 — `translations` (правки переводов), 0024 — `broadcasts.text_en` (английский текст рассылки)): `users`, `visits`, `broadcasts`, `broadcast_queue`,
`calendar_tokens`, `board_*` (бывший чат: не используются, сообщения стираются через 30 дней),
`schedule_edits`, `group_snapshots`, `subgroups`, `lesson_tags`, `teacher_reviews`, `review_reports`, `place_edits`, `calendar_edits`, `tg_updates` (повторы обновлений Telegram), `admin_log` (действия владельца,
в интерфейсе не показывается), `usage_daily` (расход лимитов, режим экономии), `hidden_lessons` (скрытые пары: свои и `user_id = 0` — для всей группы). Группа (`users.grp` и т. п.) — id.
**KV** (редкие записи, лимит 1000/сутки): `chats` (настройки бесед, тема форума; группа — id), `settings`
(приветствия, техработы, объявление, канал новостей), `sent:<дата>:<слот>` (уже отправленные сводки, TTL 3 дня),
`alerts-sent` (присланные тревоги). Старые `snapshot:1-1|1-2` и `board-snapshot:<id>` больше не используются.

**Команды бота.** Личка: `/start` (одно из 3 приветствий), `/today`, `/tomorrow`.
Личка, всем: `/deleteme` — удалить свои данные (с подтверждением; отзывы обезличиваются, бан остаётся).
Владелец (у остальных молчат): `/stats`, `/usage` (расход лимитов), `/backup` (бэкап D1 сейчас), `/broadcast`, `/broadcasts`, `/export`, `/ban`, `/unban`, `/bans`.
Беседы: `/setup` (админы: кнопки 1-1/1-2 или `/setup название`
— поиск по всем группам; потом время 7:00/7:30/8:00/выкл),
`/today`, `/tomorrow`, `/here` (рассылка в эту тему форума), `/off`. Inline: `@GUU_Scheduule_bot сегодня|завтра|пн…сб|неделя`.

## Команды

```bash
npm run dev                      # фронт; ?tg&uid=7&name=… — эмулятор Telegram (src/dev/telegram-mock.ts)
npm run build                    # tsc -b && vite build → dist/
cd bot && npm run check          # wrangler types + tsc
cd bot && npm run deploy         # деплой воркера, затем: curl https://guu-schedule-bot.guu-schedule-bot.workers.dev/?force
cd bot && npx wrangler d1 migrations apply guu-bot --remote   # и проверить: … migrations list guu-bot --remote
```
Сайт деплоится только через push в main (GitHub Actions). Локально: `bot/.dev.vars` (тестовый токен
`123456:LOCAL-TEST-TOKEN`, `TELEGRAM_API`/`GITHUB_API` на поддельные сервера, `WEBAPP_URL=http://localhost:5173/`
— данные с локального Vite) и `.env.development.local` (`VITE_BOT_URL=http://127.0.0.1:8787`) — оба в
.gitignore, в git не класть. Локальный cron: `/cdn-cgi/handler/scheduled?cron=*+*+*+*+*&time=<мс>`.
Перевод приложения: `npm run i18n` (нет русского текста мимо t(), у всех строк есть английский; в CI).
Автотесты воркера: `cd bot && npm test` (vitest в рантайме Workers, `bot/test/`; в CI — `.github/workflows/tests.yml`).
Бэкапы D1 и восстановление — `docs/backup.md`.

`BOT_TOKEN`, `OWNER_ID` (Telegram ID владельца), `BOARD_SALT` (был ключ псевдонимов чата — с этапа 9 не нужен),

Только для локальной проверки: `TELEGRAM_API`, `GITHUB_API`. Vars в `wrangler.jsonc`: `WEBAPP_URL`,
`BOT_USERNAME`, `GITHUB_REPO`, `GITHUB_WORKFLOW`. **Секреты вводит владелец сам** — не вводить за него,
не писать в код, git и чат.

## Правила и решения

- Большие задачи — по этапам: проверить → коммит + push → деплой воркера и сайта → следующий этап.
  Не получилось — остановиться и сказать, остальное не ломать.
- Главный экран — расписание своей группы (у МБ — переключатель 1-1 / 1-2, у остальных — своя + избранные).
  Нижнее меню: «Расписание», «Другое», «Профиль» (спорта нет). Всё новое — внутри «Другого»: Преподаватели (рейтинг), Сессия, Календарь на телефоне,
  Бот в беседе группы, «Админ-панель» (только владельцу, у остальных ни пункта, ни намёка).
  На расписании никаких попапов/баннеров, кроме объявления из админки (плашка с крестиком).
  Цвета — тема Telegram.
- Админ = `OWNER_ID`; права проверяет воркер (подпись initData или chat id), не только фронт.
  Все записи из приложения — через воркер с проверкой initData (не старше суток).
- Любая ошибка: пользователю «Что-то сломалось 🛠», владельцу в личку — текст ошибки (`errors.ts`).
- Частые записи — D1, KV — только редкие. Укладываться в бесплатные лимиты (50 подзапросов на вызов,
  10 мс CPU, D1 100 тыс. записей/сутки).
- Чётность недели: `неделя % 2 === 0` — чётная; 1-я неделя с `semester_start` (31.08.2026);
  20.10.2026 — 8-я, чётная.
- Файлы групп (`public/data/schedule/*.json`) — чистый вывод парсера. Правки — поверх, в `makeTimetable`
  (группа в правках — id или имя МБ): `overrides.json`
  (remove/add пар) → замены дня целиком (`overrides/thursday.json` — **четверг МБ(МП) 1-1**, `overrides/thursday-1-2.json` — **четверг 1-2**; все пары ГУУ
  заменяются, `even`/`odd` по чётности, тип «Практика», весь семестр). Новый файл замены — добавить в
  `DATA_FILES` (vite.config.ts), импорт в `src/schedule.ts` и `REPLACEMENT_FILES` в `bot/src/schedule.ts`.
- Разовые правки — D1 `schedule_edits` (отмена, пометка, перенос, добавить пару): владелец (админка) и старосты
  (`users.starosta_of`, «Ещё → Правки группы», `bot/src/starosta.ts`, только своя группа); владелец видит автора
