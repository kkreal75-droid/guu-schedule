## Общие правила

- Университет один — ГУУ (Государственный университет управления).
  Выбора вуза в интерфейсе нет.
- Не ломай существующее: расписание, профиль, заметки, приветствие /start,
  /stats, рассылки, бан, экспорт, inline-режим, бот в беседах (с темами),
  календарь, админ-панель, ручные правки (включая четверг МБ 1-1/1-2),
  автообновление.
- Главный экран — расписание своей группы. Всё новое — ненавязчиво
  в «Ещё». Нижнее меню: «Расписание», «Ещё», «Профиль».
- Сейчас всё приложение бесплатно для всех: никаких замков, кнопок
  оплаты и упоминаний подписки.
- Все записи только через воркер с проверкой подписи initData.
  Админ = OWNER_ID. Секреты — только через `wrangler secret put`, вводит владелец сам.
- Всё в try/catch, ошибки — владельцу в личку.
- Остаёмся на текущей инфраструктуре. Проверить бесплатные лимиты KV/D1
  для ~1000 пользователей; если не влезаем — сказать до реализации.

## Этап 1. Данные всего ГУУ

1. update.py: скачивать ВСЕ файлы с https://guu.ru/student/schedule/
   (бакалавриат ОФО 1–4, ОЗФО 1–5, магистратура, аспирантура; .doc УМБ —
   конвертировать через LibreOffice headless) и с https://guu.ru/student/session/.
   Изменения отслеживать по SHA-256.
2. Универсальный парсер на основе parser.py (логику разбора ячеек, недель,
   «/», объединённых ячеек сохранить): все листы, все колонки групп; шапку
   (институт / направление / программа / № группы) искать по подписям в
   колонке A с учётом объединённых ячеек; сетку времени брать из файла
   (у ОЗФО и аспирантуры она другая); пустые «раздутые» строки пропускать.
3. У каждой группы стабильный id и читаемое имя. Выход: groups.json,
   schedule/<group_id>.json, teachers.json (преподаватель → пары и группы),
   rooms.json (аудитория → занятость), session/<group_id>.json.
4. parse_report.json: группы и пары по каждому файлу/листу, нераспознанные
   ячейки. Если число групп в файле упало >10% против прошлой версии —
   файл не публиковать, владельцу тревогу в бот.
5. Тест: МБ(МП) 1-1, пн 19.10.2026, 9:00 — ОПУ, Денисова И.В., У-432.
   Ручная правка четверга МБ 1-1/1-2 сохраняется.
6. Текущих пользователей МБ(МП) 1-1 и 1-2 автоматически перенести на новые id.

В конце — сводка: сколько групп по уровням и курсам, где парсер не уверен.

## Этап 2. Онбординг и выбор группы

Онбординг при первом входе (новый пользователь без сохранённой группы):
1. Приветствие: «Расписание твоей группы в ГУУ. Настроим за 30 секунд» +
   кнопка «Начать».
2. «Кто ты»: Студент / Преподаватель.
3. Студент: форма → уровень → курс → институт → программа → группа.
   Каждый шаг — экран с крупными кнопками-карточками (не выпадающие
   списки), прогресс сверху, кнопка «Назад». Шаги с единственным вариантом
   пропускать. На любом шаге кнопка «Знаю свою группу» — поиск по всем группам.
   Преподаватель: поиск по фамилии из teachers.json → его расписание
   становится главным экраном.
4. Финал: открывается обычный экран «Расписание» с выбранной группой.

Пожелания владельца по виду (20.10, скриншоты онбординга другого приложения ГУУ):
- первый экран — «Привет! Я Кирилл, студент 1 курса» (автор приложения) + «Расписание
  твоей группы в ГУУ. Настроим за 30 секунд» + «Начать»;
- как у них: полоска прогресса сверху, «Шаг N из M», выбранное — чипсами с крестиком,
  крупные карточки, «Назад»; но удобнее: тап по карточке сразу ведёт дальше (без
  отдельной «Продолжить»), шаги с одним вариантом пропускаются, на группе — полное имя
  («МБ(МП) 1-1»), а не просто «1», поиск «Знаю свою группу» на каждом шаге;
- никаких экранов про подписку, цены и «Оформить подписку».

Выбор сохранять в базу (через воркер) и в CloudStorage Telegram.
Онбординг не показывается повторно; в «Профиле» — кнопка
«Сменить группу / роль», которая запускает его заново.

Режим МБ(МП) 1-1 и 1-2:
- Существующие пользователи с группами 1-1/1-2 онбординг НЕ видят,
  у них всё как сейчас.
- У всех пользователей с группой МБ(МП) 1-1 или 1-2 (старых и новых) над
  расписанием переключатель «1-1 / 1-2», как сейчас.
- У остальных над расписанием только их группа + избранные группы
  (добавляются кнопкой «★ В избранное» в «Ещё → Расписание группы»).

Подготовка к будущей оплате (НЕ включать):
- Конфиг PAYWALL_ENABLED=false.
- Поле access у пользователя: 'free_forever' — для групп МБ(МП) 1-1 и 1-2
  и для всех, кто уже есть в базе на момент релиза; 'standard' — для
  остальных. В админке — выдать/забрать free_forever вручную.
- Только структура, логику платного доступа не реализовывать.

Для любой группы: inline-режим, беседы (/setup — выбор группы поиском),
календарь, рассылка (аудитория: все / уровень / курс / институт / группа),
вкладка «Сессия» своей группы.

## Этап 4. Старосты

- В админке: назначить пользователя старостой группы / снять.
- Староста видит в «Ещё» пункт «Правки группы»: добавить пару, отменить,
  пометка, перенос — только для своей группы. Все правки видны владельцу
  в админке с автором, можно откатить. Правки работают везде (приложение,
  inline, беседы, календарь), автообновление их не трогает.
- Языковые подгруппы: староста создаёт подгруппы (например «Англ —
  Цунаева», «Англ — Замятина»); пара может принадлежать подгруппе;
  студент выбирает свою подгруппу в профиле и видит только свои пары.

### 7.1 Онбординг — ДЛЯ ВСЕХ, включая уже зарегистрированных
Показывается один раз каждому пользователю при следующем запуске (флаг onboarding_version=2
в базе и CloudStorage). Уже зарегистрированных НЕ заставлять заново проходить 7 шагов:
